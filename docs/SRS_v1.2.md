**Version 1.2**
**작성일**: 2026-05-20 (v1.0) / 2026-05-20 (v1.1 개정) / 2026-05-21 (v1.2 개정)
**작성자**: 이상우
**대상 플랫폼**: Arduino UNO Q (Linux MPU + STM32 MCU 듀얼 아키텍처)
**개발 환경**: Arduino App Lab (Python on MPU + Sketch on MCU)

## 1. 개요

### 1.1 프로젝트 목적
화면에 표시되는 색상 시퀀스를 사용자가 기억하여 동일한 순서로 실제 물리 버튼을 눌러 재현하는 기억력 게임을 Arduino UNO Q 단일 보드에 내장형으로 구현한다. 단계가 진행될수록 사용 가능한 색상의 수와 시퀀스 길이가 함께 증가하여 난이도가 상승한다.

### 1.2 대상 사용자
- **1차**: 초등학생 (체험 활동, 전시 부스 방문자)
- **2차**: 일반 방문객 (메이커 페어, 교육 시연 참관자)

### 1.3 운영 형태
부팅 시 자동 실행되어 PC 연결 없이 독립 동작하는 키오스크형 임베디드 애플리케이션. App Lab의 "Run at startup" 기능으로 전원 인가 시 즉시 게임 시작.

### 1.4 핵심 키워드
임베디드, 키오스크, Simon Says 변형, 듀얼 아키텍처, 점진적 난이도

### 2.1 부품 목록

|------|------|------|------|
| 메인 보드 | Arduino UNO Q (2GB 권장) | 1 | Linux + STM32 듀얼 아키텍처 |
| 입력(게임) | 100mm LED 아케이드 버튼 (빨강) | 1 | 마이크로스위치 + 5V LED 내장 |
| 입력(게임) | 100mm LED 아케이드 버튼 (파랑) | 1 | 동일 사양 |
| 입력(게임) | 100mm LED 아케이드 버튼 (노랑) | 1 | 동일 사양 |
| 입력(게임) | 100mm LED 아케이드 버튼 (초록) | 1 | 동일 사양 |
| 입력(닉네임) | (터치모니터 자체 사용) | - | USB 키보드 불필요 |
| 출력 | **터치스크린 모니터** (24인치 이상 권장) | 1 | HDMI + USB 터치 신호, 정전식 권장 |
| 부속 | USB-C 도크 (HDMI + USB-A 허브 + 전원) | 1 | HDMI 출력 + 터치 USB 신호 통합 |

| 부속(권장) | **RTC 백업 배터리 (CR2032)** | **1** | **스코어보드 timestamp 신뢰성 (v1.2 추가)** |
| 케이스 | 컨트롤 패널 (합판 또는 아크릴) | 1 | 100mm 버튼 4개 거치 (구멍 100mm) |

### 2.2 핀 배치도 (STM32 MCU)

| 버튼 색상 | 스위치 입력 핀 | LED 출력 핀 | 화면 위치 |
|-----------|----------------|-------------|-----------|
| 빨강(RED) | D2 (INPUT_PULLUP) | D6 (PWM) | 좌상 |
| 파랑(BLUE) | D3 (INPUT_PULLUP) | D9 (PWM) | 우상 |
| 노랑(YELLOW) | D4 (INPUT_PULLUP) | D10 (PWM) | 좌하 |
| 초록(GREEN) | D5 (INPUT_PULLUP) | D11 (PWM) | 우하 |

**결선 규칙 (v1.2 명확화):**
- **스위치**: COM 단자 → GND, NO 단자 → 해당 GPIO 핀 (INPUT_PULLUP)
- **LED (Low-side 스위칭 단일화)**:
  ```
  5V ──[220Ω]── LED(+) ── LED(-) ── [MOSFET Drain]
                                       │
                            [Gate] ◄── GPIO PWM (via 1kΩ)
                            [Source] ── GND
  ```
- UNO Q의 STM32U585는 **3.3V 로직**이므로 5V LED를 GPIO로 직접 구동할 수 없다. **N-채널 MOSFET 또는 NPN TR을 통한 Low-side 스위칭이 필수**이다. (v1.1의 모호한 "또는" 표현을 v1.2에서 단일화)

### 3.2 분담 원칙
- **MCU**: 실시간 하드웨어 I/O (밀리초 단위 정확성 요구). 시퀀스 시연 타이밍도 MCU에서 직접 수행하여 ±20ms 정확도 보장 (v1.2).
- **MPU**: 게임 로직, 화면 출력, 데이터 저장 (높은 계산량, 비결정적 작업)

### 3.3 RPC 브리지 인터페이스

App Lab의 Brick(RPC) 메커니즘으로 정의되는 함수:

| 방향 | 함수명 | 인자 | 반환 | 설명 |
|------|--------|------|------|------|
| Python → MCU | `light_button(color, duration_ms)` | 색상코드, 점등시간 | OK | 단일 버튼 LED 점등 (피드백용) |
| Python → MCU | `play_sequence(colors[], on_ms, off_ms)` | 색상 배열, on/off 간격 | OK | **시퀀스 전체를 MCU 단독 시연 (v1.2 신규)** |
| Python → MCU | `set_all_leds(state)` | on/off | OK | 게임 시작/종료 시 전체 LED 제어 |
| Python → MCU | `attract_mode_leds(enable)` | bool | OK | 대기 모드 LED 순환 점멸 on/off |
| Python → MCU | `arm_input(active_colors[], timeout_ms)` | 활성 색상 목록, 타임아웃 | OK | 입력 대기 모드 진입 (단계별 활성 색상 한정) |
| Python → MCU | `selftest()` | - | 상태표 | **각 버튼/LED 자가진단 (v1.2 신규)** |
| Python → MCU | `get_firmware_version()` | - | "X.Y.Z" | **MCU 펌웨어 버전 (v1.2 신규)** |
| MCU → Python | `button_pressed(color, ts)` | 색상, 타임스탬프 | - | 버튼 입력 이벤트 (비동기 푸시) |
| MCU → Python | `sequence_done()` | - | - | **시퀀스 시연 완료 통지 (v1.2 신규)** |

**비활성 색상 처리 (v1.2 신규):** `arm_input`의 `active_colors`에 포함되지 않은 색상 버튼이 눌리면 MCU는 해당 이벤트를 **드롭**하고 MPU에 전송하지 않는다. 짧은(50ms) 거부 점멸을 해당 LED에 표시한다.

### 4.2 단계별 난이도 진행 규칙

| 단계 | 활성 색상 | 시퀀스 길이 | 제한시간 |
|------|-----------|-------------|----------|
| 1 | 빨강, 파랑 (2색) | 2 | 버튼당 10초 |
| 2 | 빨강, 파랑, 노랑 (3색) | 3 | 버튼당 10초 |
| 3 | 빨강, 파랑, 노랑, 초록 (4색) | 4 | 버튼당 10초 |
| 4 | 4색 전체 | 5 | 버튼당 10초 |
| 5 | 4색 전체 | 6 | 버튼당 10초 |
| ... | 4색 전체 | n+1 | 버튼당 10초 |
| 20 (최종) | 4색 전체 | 21 | 버튼당 10초 |

**규칙 상세:**
- 시퀀스는 매 단계마다 새로 생성 (이전 시퀀스 + 1색 추가 방식이 아닌, 완전 신규 생성)
- 시퀀스 내 동일 색상 중복 허용. 단, **동일 색상이 4회 이상 연속되지 않도록 RNG 후처리에서 거부 샘플링** (v1.2 신규)
- **RNG 시드**: 부팅 시 `os.urandom(8)` 으로 초기화. 게임 세션마다 동일 시드를 다시 사용하지 않음 (v1.2 신규)
- 20단계 클리어 시 "CLEAR!" 화면 표시 후 점수 확정
- 점수 = 클리어한 단계 수 (1단계 클리어 시 1점, 최대 20점)

### 4.3 시퀀스 시연 방식 (SHOW_SEQUENCE 상태)
- 각 색상은 **500ms 점등 + 200ms 휴지** 간격으로 순차 표시 (v1.2에서 고정 확정)
- 화면의 색상 블록과 물리 버튼 LED가 동시에 점등
- 시연 중 모든 사용자 입력 무시 (MCU가 `arm_input` 전이므로 자체 차단)
- 시연 타이밍 정확도는 MCU에서 직접 보장(±20ms). MPU는 `play_sequence` 호출 후 `sequence_done` 이벤트를 기다린다.
- 단계별 시연 속도 차등화는 **v1.3 검토 사항으로 이관** (v1.2 확정)

### 4.4 사용자 입력 처리 (USER_INPUT 상태)
- 시연 종료 직후 입력 대기 시작
- **제한시간은 버튼 입력 1회당 10초** (각 입력마다 카운트다운 재시작)
- 화면 우상단의 ⏱ 카운터는 다음 버튼을 누를 때까지 남은 시간을 표시 (1초 단위 갱신)
- 사용자가 **활성 색상** 버튼을 누를 때마다:
  - 해당 위치의 화면 블록 + 물리 LED가 200ms 점등
  - 즉시 시퀀스와 대조하여 정/오답 판정
  - 정답이면 카운트다운을 10초로 리셋 후 다음 입력 대기
  - 오답 즉시 GAME_OVER로 전환
- **비활성 색상 버튼**을 누를 경우(예: 1단계에서 노랑/초록): 입력을 **무시**하고 해당 LED에 50ms 거부 점멸만 표시한다. 시퀀스 진행에 영향 없음. (v1.2 신규)
- **화면 터치를 통한 입력**: USER_INPUT 상태에서 화면의 4분면 색상 블록을 직접 터치해도 동일하게 입력으로 인정한다(접근성 향상). 단, 터치/버튼 동시 입력은 먼저 감지된 것만 인정. (v1.2 신규)
- 10초 내 다음 버튼 입력이 없으면 타임아웃 → GAME_OVER로 전환
- 시퀀스 전체 입력 완료 시 LEVEL_CLEAR로 전환

### 4.4.1 LEVEL_CLEAR 처리 (v1.2 신규)
- 화면: "LEVEL n CLEAR" 1.5초 표시
- 물리 버튼 LED: 활성 색상 전체 동시 점등 300ms × 2회
- 사운드(있을 경우): 짧은 상승 팡파레
- 1.5초 종료 후 자동으로 다음 단계 SHOW_SEQUENCE 진입

### 4.5 게임 종료 처리 (GAME_OVER 상태)
- 화면: "GAME OVER" + 최종 점수 표시 (3초)
- 물리 버튼 LED 깜빡임: **모든 버튼이 200ms ON / 200ms OFF 를 5회 반복** (총 2.0초). 화면 표시와 동시 시작, LED는 먼저 종료. (v1.2 명확화)
- 짧은 부저음 (있을 경우): 하강 2음
- 신기록 판정:
  - **스코어보드가 비어 있거나 항목 수가 10개 미만**이면 무조건 닉네임 입력 화면으로 진입 (v1.2 신규)
  - **현재 점수 > 스코어보드 10위 점수** → 닉네임 입력 화면
  - **현재 점수 == 기존 항목 점수** → "동점이지만 기록 갱신" 안내 후 닉네임 입력 화면 진입(기존 동점자 위로 올라가지 않고 직하단 삽입). (v1.2 명확화)
  - 그 외 → 3초 후 ATTRACT 복귀

### 4.6 닉네임 입력 처리
- **터치모니터의 화면 가상자판(앱 내장)** 사용
- 키보드 미연결 상태에서도 동작 (USB 키보드 불필요)
- 가상자판 레이아웃:
  - 영문 대문자 A~Z (QWERTY 배치)
  - 숫자 0~9
  - 기능 키: [⌫ 삭제], [확인], [취소]
- 입력 형식: 영문 대문자/숫자 1~10자 (공백/특수문자 불가)
- [확인] 터치로 확정 후 **즉시 ATTRACT 복귀**(추가 점수화면 없음)
- [취소] 터치 시 **"ANONYMOUS"로 저장 후 즉시 ATTRACT 복귀** (v1.2 명확화)
- 30초 무입력 시 "ANONYMOUS"로 자동 저장 후 ATTRACT 복귀
- 입력 중인 닉네임은 가상자판 상단의 입력창에 실시간 표시 (커서는 `_` 로 표현)
- 키 터치 시 시각적 피드백(키 색상 반전 100ms) 제공
- **연속 동일 키 터치 디바운싱**: 같은 키 200ms 이내 재입력 무시 (예외처리 표 참조)
- 한글 입력은 지원하지 않음 (v1.3 검토)

### 4.6.1 가상자판 화면 레이아웃 (1920×1080 기준)

### 4.7 ATTRACT 모드
- 30초간 무입력 시 자동 진입
- 화면: 게임 타이틀, 조작 안내("아무 버튼이나 누르거나 화면을 터치하세요"), **Top 10 점수 슬라이드 표시** (v1.2: Top 5 → Top 10 통일)
- 물리 버튼 LED: 1초 간격으로 R→B→Y→G 순환 점멸
- **임의의 물리 버튼 입력 또는 화면 터치 시 READY 상태로 전환** (v1.2: "키보드 입력" 문구 제거)
- ATTRACT를 깨운 입력은 **소비**되며, 게임 시작 후 첫 입력으로 카운트되지 않음

### 4.8 READY 상태 (v1.2 신규 명세)
- 3초 카운트다운 화면 ("3...2...1...GO!")
- 카운트다운 중 **모든 버튼 입력 및 터치 무시**(가속/취소 불가)
- 0초 도달 시 SHOW_SEQUENCE로 자동 전이

### 4.9 운영자 유지보수 기능 (v1.2 신규)
키오스크 OS는 일반 사용자에게 잠겨 있으므로, 다음 유지보수 진입 방법을 제공한다:

| 기능 | 진입 방법 | 동작 |
|------|-----------|------|
| 자가진단 모드 | ATTRACT에서 빨강+초록 버튼 5초 동시 누름 | 각 LED 순차 점등, 각 버튼 입력 표시 |
| 스코어보드 초기화 | 자가진단 모드 화면의 "RESET SCORES" 터치 → 확인 | scoreboard.json 백업 후 빈 보드로 초기화 |
| 시스템 종료 | 자가진단 모드 화면의 "SHUTDOWN" 터치 → 확인 | `sudo shutdown -h now` 실행 |
| 재부팅 | 자가진단 모드 화면의 "REBOOT" 터치 → 확인 | `sudo reboot` 실행 |
| 버전 표시 | 자가진단 모드 첫 화면 | MPU 앱 버전, MCU 펌웨어 버전 표시 |

- MPU 앱 시작 시 `get_firmware_version()` 호출하여 MCU 펌웨어 호환 버전(major) 매칭 검증. 불일치 시 ATTRACT 진입 전에 에러 화면 표시.

### 5.2 스코어보드 운영 규칙
- 최대 10개 항목 유지 (점수 내림차순)

- 매 게임 종료 후 신기록 진입 여부 판정 → JSON 갱신
- **저장은 원자적(atomic)**: 임시 파일에 쓰고 `os.replace()` 로 교체하여 정전 시 손상 방지 (v1.2 신규)
- 보드 한 대 내에서만 보존 (네트워크 동기화 없음)
- 백업: USB 메모리 삽입 시 자동 백업 (선택 기능, **v1.3 검토 이관**)

## 7. 비기능 요구사항

### 7.1 응답 속도
- 물리 버튼 입력 → 화면/LED 반응: **100ms 이내** (LED는 MCU에서 직접 응답하므로 20ms 이내 보장 가능)
- 시퀀스 시연 타이밍 정확도: **±20ms 이내**, MCU에서 직접 수행(MPU의 RPC 왕복 시간 영향 차단)

### 7.2 안정성
- 24시간 연속 가동 시 메모리 누수 없음
- 게임 1,000회 반복 후에도 크래시 없음
- 정전 후 재부팅 시 자동으로 ATTRACT 모드 진입
- **자동 복구 (v1.2 신규)**:
  - MPU 게임 프로세스는 systemd unit으로 등록, `Restart=always`, `RestartSec=2s`
  - systemd watchdog 사용 (60초 무응답 시 강제 재시작)
  - MCU-MPU RPC 단절 시 MPU에서 최대 3회 재연결 시도, 실패 시 에러 화면 표시 후 60초 뒤 프로세스 자살 → systemd 재기동

### 7.3 부팅 자동실행
- systemd `memorygame.service` 등록 (App Lab의 "Run at startup" 기능 사용)
- 전원 인가 후 60초 이내 ATTRACT 모드 진입

### 7.4 유지보수성
- 시퀀스 길이, 제한시간, 색상 매핑 등 모든 운영 파라미터는 `config.yaml` 외부화 (스키마는 5.4 참조)
- 로그 파일: `/home/arduino/game.log` (rotation 적용, 최대 10MB × 3 backup)
- 운영자 자가진단/초기화 기능은 4.9 참조

### 7.5 접근성
- 색맹 사용자 고려: 색상 블록 내부에 도형(▲■●◆) 표시 (`config.yaml`에서 토글, v1.2)
- 화면 글자 크기: 최소 36pt 이상
- 터치 입력을 통한 게임 진행 가능(물리 버튼 거동 불편 사용자 배려, 4.4 참조)

### 7.6 전원 (v1.2 신규)
- 입력 전원: DC 5V / 4A 이상 (UNO Q + LED 4 × 약 100mA + USB-C 도크 합산 여유)
- 모니터는 별도 콘센트 사용
- 권장: UPS 또는 멀티탭에 서지보호

### 7.7 보안 / 키오스크 락다운 (v1.2 신규)
- 부팅 후 자동 로그인, X 세션 시작과 동시에 전체화면 게임 실행
- 키 조합 차단: `Ctrl+Alt+F1~F6`, `Ctrl+Alt+Del`, `Alt+Tab`, `Super` 키 무력화 (xkb 설정)
- USB 자동 마운트: **자가진단 모드에서만** 활성(v1.3 USB 백업 기능과 연계). 평시는 `udisks2` 정책으로 차단
- 화면 우클릭/컨텍스트 메뉴 차단

### 7.8 시각 동기화 (v1.2 신규)
- 본 시스템은 네트워크 미사용을 전제로 한다
- RTC 백업 배터리(CR2032)를 보드에 장착하여 timestamp 신뢰성 확보
- 운영자가 자가진단 모드에서 현재 시각을 수동 설정할 수 있도록 시각 설정 UI 제공
- 시각 설정 불가/배터리 방전 시 로그 및 스코어보드의 `date` 필드는 부팅 후 단조 증가 epoch 기록(상대시각)으로 폴백, 절대시각 부정확 경고를 자가진단 화면에 표시

## 10. 검증 기준

| 항목 | 측정 방법 | 목표값 |
|------|-----------|--------|
| 1단계 클리어 성공률 | 초등 3~4학년 **30명 이상** 테스트 (v1.2 표본 확대) | 90% 이상 |
| 10단계 이상 도달 비율 | 동일 그룹 테스트 (v1.2: "최종 단계"는 비현실적이므로 10단계로 하향) | 10% 이상 |
| 평균 플레이 타임 | 게임 시작~종료 | 1~3분 |
| 입력 응답 지연 (MCU LED) | 오실로스코프 측정 (버튼 신호 → LED 점등) | 30ms 이하 |
| 입력 응답 지연 (화면 블록) | 화면 캡처 보드 측정 | 100ms 이하 |
| 시퀀스 시연 타이밍 오차 | 오실로스코프로 LED 점등 간격 측정 | ±20ms 이내 |
| 24시간 연속 동작 | 자동 반복 테스트 + systemd 재시작 카운트 | 크래시 0회, 자동복구 동작 확인 |
| 스코어보드 정전 내성 | 쓰기 중 강제 전원차단 100회 반복 | 손상 0회 |
| RNG 동일색 연속 분포 | 1,000회 시퀀스 생성 시 동일색 4연속 출현 | 0회 |

## 부록 A: 용어 정리

| 용어 | 설명 |
|------|------|
| MCU | Microcontroller Unit, UNO Q의 STM32U585 칩, 실시간 제어 담당 |
| MPU | Microprocessor Unit, UNO Q의 Qualcomm Dragonwing 칩, Linux 담당 |
| RPC | Remote Procedure Call, MCU-MPU 간 함수 호출 메커니즘 |
| Sketch | Arduino C++ 코드, MCU에서 실행 |
| App Lab | Arduino의 통합 개발환경, UNO Q 전용 |
| eMMC | 보드 내장 비휘발성 저장소 (16GB or 32GB) |
| ATTRACT | 아케이드 게임 용어, 플레이 대기 중 시연 화면 |
| Debouncing | 버튼 채터링(chattering, 접점 떨림) 제거 처리 |
| Low-side 스위칭 | 부하의 GND 측에 스위칭 소자(MOSFET/TR)를 두어 전류를 단속하는 방식 |
| RTC | Real-Time Clock, 전원 차단 후에도 시각을 유지하는 보조 회로 |
| systemd watchdog | 프로세스가 주기적으로 신호를 보내지 않으면 강제 재시작하는 감시 기구 |
